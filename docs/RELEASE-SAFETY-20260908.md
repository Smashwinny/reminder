# 2.3.4 用户数据安全审查与交付记录

本轮从用户登录、记录、同步、断网重试和备份恢复路径审查。不能以健康接口或“同步成功”提示证明不会丢数据。

## 已修复的具体故障

- 同步请求发出后新增或删除任务：旧实现用响应整表替换当前列表，即使响应包含所有已上传 ID，也会丢掉请求发出后的修改。现在主线程序列化请求，响应按 ID 和更新时间合并进当时的最新本地集合。
- 账号切换快照失败：旧实现返回后调用方仍写入新令牌。现在返回明确成功状态，目标数据解析失败或快照失败则停止登录；新分区、身份和凭据在同一次提交中保存。
- 同名账号身份改变：同名不能证明是同一人。用户 ID 改变时先显示确认说明，取消保留旧账号；同服务器同名的迁移只有用户确认后才进行。
- 并发登录：迟到的旧登录结果不能覆盖最近一次登录操作。
- 本地数据损坏：不再将解析失败后的空列表上传或保存。保存失败不显示同步成功。
- 账号切换快照被日常同步挤出：快照按用户与用途分别轮转，账号迁移快照不再被普通同步覆盖。
- 网页断网后刷新：任务按账号写入浏览器存储，串行发送同步请求，响应合并保留请求途中新增内容；拒绝身份不匹配或遗漏已上传 ID 的响应。
- 网页无限等待或误导提示：请求有 20 秒超时，出错显示失败；接收结果显示云端与本地任务数量，不把单纯接收当成全部上传完成。
- 服务器文件损坏：损坏的 JSON/非数组数据不再当空库，也不允许覆盖该文件。账号库缺失但仍有历史用户/会话时，拒绝注册替代账号。
- 服务器误覆盖：写入前保留历史文件（每个文件最多 64 份），写入临时文件并 fsync 后改名。历史文件权限为 600，已加入备份脚本范围。
- 服务重启清空日志：服务与隧道日志均改为追加。Docker 构建入口同步包含新增存储模块。
- 版本默认值落后：默认正式构建版本更新为 2.3.4 / 21。

## 验证边界与后续上线要求

- 手机最后抓取时处于锁屏，安装版本已验证，最终可见界面仍需解锁验收。
- 生产用户的账号库没有进行破坏性故障注入；这类测试在隔离目录中完成。正常真实数据路径已验证。
- 历史文件和本机备份不能抵御整机磁盘损坏。正式扩大用户范围前应配置异机定时备份、监控及恢复演练。
- 网页缓存依赖浏览器站点存储；清除站点数据会清除尚未上传的缓存。切换设备前需确认云端已收到任务。
- 手机附件当前仍是本地 URI，只同步任务信息；不能把手机图片、视频在电脑打开当成已支持的功能。
- 已打开的旧网页需要刷新才能获得本次修复。其他用户仍在旧客户端时仍需升级；本轮没有自动向其他设备推送。

本轮保留了工作区已有的账号备份增强；备份脚本本次新增了历史目录覆盖及日志追加。其他已有规则和旧复盘文件不在本轮修改范围。

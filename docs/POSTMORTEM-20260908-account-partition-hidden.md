# 复盘：账号重建后手机任务分区被切换

## 影响

2026-09-08，手机登录 `hulk` 后，界面任务从 71 条本地任务切换为 45 条，网页同步成功但看不到手机新增任务。
旧任务没有被物理删除，而是仍保存在旧用户 ID 对应的 SharedPreferences 分区中。

恢复时将旧分区 71 条与当前账号分区 45 条按任务 ID 合并：共有 44 条、旧分区独有 27 条、
当前分区独有 1 条，最终得到 72 条（已完成 2 条）。恢复结果已同时写回生产账号和手机当前分区。

## 根因

多用户客户端使用服务器生成的用户 ID 作为本地任务分区键。账号认证数据重建后，同一用户名获得了新的用户 ID。
旧版 `switchLocalAccount()` 只比较用户 ID：ID 不同就保存旧分区、清空内存列表并加载新分区。
它没有识别“同一服务器上的同一用户名被重建”，也没有在整表替换前建立恢复快照或校验同步响应是否包含本地任务。

新账号中出现的 44 条旧任务来自 2026-09-04 执行的旧版公共任务迁移；之后新增 1 条，所以事故现场显示 45 条。
“同步成功”仅表示这 45 条所在的新分区与服务器同步成功，不代表旧用户 ID 分区中的任务已经上传。

## 修复

1. 同一服务器、同一用户名但用户 ID 变化时，先按任务 ID 和更新时间合并旧、新本地分区，再发起云端合并。
2. 账号切换和 `merge` 整表替换前，同步写入三槽轮转的本地恢复快照；快照写入失败则拒绝覆盖。
3. `merge` 响应必须包含请求中上传的全部本地任务 ID；缺少任何 ID 都拒绝替换本地任务。
4. 不同服务器或不同用户名仍保持严格分区，避免跨账号泄漏。

## 验证

- 安全测试构建在真实手机上生成了含 72 条任务的 `before_merge_response` 快照。
- 最终不可调试正式构建 `2.3.3-sync-safety` 在真实手机与 `https://reminder.geniusqi.com`
  同步后，手机和服务器均保持 72 条、已完成 2 条。

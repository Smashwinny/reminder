# 复盘：2026-09-04 账号认证数据丢失导致无法登录

## 2026-09-08 更正（优先于下方历史推断）

此前“生产从未生成账号、云端迁移从未执行”的结论不成立：当时只检查了本机，却把它当成唯一生产环境。
本次真实检查发现阿里云原账号仍存在且有 70 条任务，本机另有同名新账号。两台机器的 cloudflared 使用相同隧道令牌，
却连接独立的账号与任务库；公网访问可能分流，造成登录时好时坏、任务数量不同。不能由某一台机器没有数据推断所有数据丢失。

本轮停写备份后合并为 73 条任务，旧账号作为身份别名保留会话，统一读取阿里云任务库；本机旧服务禁用，启动脚本加入保护。
下面保留原复盘作为错误诊断记录，不应继续引用其中已被推翻的根因。新验收记录见 RELEASE-SAFETY-20260908.md。

## 事件摘要

用户在手机上突然无法用之前的账号密码登录拾遗。排查发现：**生产服务器上从来没有任何账号数据**——
`sync-server/data/` 目录自 8月31日 16:16 起没有任何文件增删，而多用户账号系统是 8月31日 19:03 才提交的
（`f1323b5`）。账号数据从未在真实实例上持久化过。

任务数据本身没丢（旧版 `tasks.json`，44 条），已通过 `migrate-legacy.js` 迁移到新账号 `hulk`。

## 时间线

| 时间 | 事件 |

## 根因（按责任排序）

1. **破坏性变更直接 OTA 全量推送，服务器侧迁移却从没执行。**
   认证方式从同步码换成账号密码是 breaking change。代码合并后没有任何一步在**真实运行实例**上
   注册账号、跑 `migrate-legacy.js`、验证端到端登录。所有测试都在 `tmp/multi-user-test-*`
   临时目录里做，测完即弃，生产环境一次都没验证过。

2. **部署配置与代码脱节。**
   `auth-store.js` 要求 `REGISTRATION_INVITE_CODE` 环境变量（≥12 位），否则注册直接报错；
   但生产用的 systemd 单元 `reminder-autostart.service` 从未配置它。等于生产环境**注册功能
   从上线起就是坏的**，没有任何检查发现这一点。

3. **账号数据零备份。**
   `bin/reminder backup` 只备份旧版单文件 `tasks.json`；`users.json`、`sessions.json`、
   `users/` 目录不在任何备份范围内。账号数据一旦丢失无从恢复（本次实际是没生成过）。

4. **日志无法追溯。**
   `internet-daemon` 每次启动都 `: > "$LOG_FILE"` 清空日志，事故发生后无法回看
   注册/登录历史，加大了排查难度。

## 已落地的修复

- systemd 单元已配置 `REGISTRATION_INVITE_CODE`，注册通道恢复（邀请码存于 `tmp/registration-invite-code`，权限 600）
- 用户重新注册账号 `hulk`，`migrate-legacy.js` 已把 44 条旧任务归属到该账号
- `bin/reminder backup` 现在同时打包 `users.json` / `sessions.json` / `users/` 为
  `auth-manual-*.tar.gz`（权限 600）

## 防复发规则（所有智能体必须遵守，已写入项目 CLAUDE.md）

1. **破坏性变更（认证、协议、数据格式）未在真实实例完成迁移和端到端验证前，禁止推送 OTA / 发布客户端。**
2. **代码新增必填环境变量时，必须同步更新所有运行入口**（systemd 单元、docker-compose、deploy 脚本），
   并在真实实例上验证该功能可用，而不是只在临时测试目录验证。
3. **新增持久化数据文件时，必须同步加入备份范围。**
4. **过渡期保持向后兼容**：旧认证方式至少保留一个版本周期，确认所有客户端迁移完成后再移除。
5. **日志只做滚动追加分片，禁止启动时清空**，事故后要能回看。
